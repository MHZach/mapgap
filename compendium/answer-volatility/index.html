AI Answer Volatility

AI answer volatility is the variation in what an AI assistant returns when the identical prompt is asked again within one period: different brands, a different order, different cited sources on some platforms. Even settings meant to make answers repeatable do not guarantee identical outputs, so a single answer is a sample, not a reading. Visibility is therefore reported as a rate over a fixed prompt set, with the number of prompts and runs stated and a noise band per slice.

Consensus definition

AI answer volatility is the variation in the output of a generative AI system across repeated runs of the identical prompt within one period. In a study by SparkToro with Gumshoe.ai, 600 volunteers keeping their usual settings ran 12 prompts through ChatGPT, Claude and Google's AI a combined 2,961 times. For ChatGPT and Google's AI, any two responses to the same prompt had a less than 1 in 100 chance of carrying the same brand list, and two lists in the same order came up about once in 1,000 runs1. Repeated runs submitted on the same day through the APIs of four AI search engines were about as dissimilar in their cited sources as runs on consecutive days2. The spread cannot be switched off from the user's side. OpenAI and Microsoft document that determinism is not guaranteed even with a fixed seed and a matching system fingerprint34; Anthropic tells developers to omit temperature, top_p and top_k on its current Opus models and states that temperature 0 never guaranteed identical outputs5. On an open model, 1,000 samples of one prompt at temperature 0 produced 80 distinct completions, traced to inference kernels that are not batch-invariant while batch sizes change with server load; with batch-invariant kernels all 1,000 were identical6. Research on five models configured to be deterministic found accuracy varying by up to 15% between ordinary runs of the same task in the worst case7. Default settings can add sampling by design, changes in retrieval and personalisation on top; no source we reviewed separates their shares. Week-on-week replacement of cited sources is a neighbouring phenomenon, citation rotation, read against the same noise (see AI Citation Decay).

rhinegold operator refinement

Rhinegold's position: a single AI answer is a sample, not a reading. Visibility is reported only as a rate over a fixed prompt set, with the number of prompts and runs per prompt stated, each figure carries a noise band for its slice, and a change smaller than that band is reported as not distinguishable from noise. The published evidence points the same way. SparkToro's data shows unstable lists but usable rates: in a separate test with 142 differently worded prompts written by people (994 responses, about seven per prompt), the leading headphone brands appeared in 55 to 77% of responses, and the authors now consider visibility percentage across dozens to hundreds of prompts, each run several times, probably a reasonable metric, but rank position unreliable1. For Google AI Mode, SISTRIX finds a stable core of a few cited domains for 86% of prompts, while the remaining domains rotate at 89% per week8. The band has to be set per slice: a slice (one platform, one prompt cluster, one market) contains fewer prompts than the total, so its band is usually wider, and a movement that is real in the overall figure can be noise in every single slice.

Operational use

Freeze the prompt set, platforms, access path and counting rules first; volatility can only be measured once the method itself is stable (Measurement Consistency). Count in fixed units: a run is one execution of one prompt on one platform and yields one answer; a rate is the number of answers naming the brand divided by the number of answers in the slice. Fix the number of runs per prompt before the first wave and print it, with the number of prompts, beside every figure. A rate over a large, fixed prompt set needs few runs per prompt; a claim about one prompt or a small slice needs more92. Measure the band instead of assuming it: run the frozen set twice in the same window, each time with the run count of one wave. This A/A repeat is the measurement-side counterpart of a placebo test: no intervention happened, so the differences between the two runs show the noise. For each slice, take the difference prompt by prompt; the band is about twice the standard deviation of these differences divided by the square root of the number of prompts in the slice, a rough 95% band that assumes the prompts vary independently. A wave-to-wave change smaller than the band of its slice is reported as not distinguishable from noise, however it looks in a chart; a slice with too few prompts is reported as a count, without a band. The band covers run-to-run spread only, not a provider update or a real change between waves. Replace rank with a distribution: report the share of runs in which a brand is named first or in the top three, not its position in one answer. Repeat the double measurement whenever platform, access path or run count changes. In an AI Visibility Audit and in ongoing LLM brand tracking, the band belongs next to every mention rate and citation rate.

Measurement boundary

The band tells you whether a change can be told apart from noise. It does not tell you why the change happened; attributing a change to an action needs a design with a comparison group, such as difference-in-differences. A run set samples one access path: API answers can differ from interface answers, and consumer interfaces add personalisation by account and conversation (API vs UI Measurement). Where seed and system-fingerprint controls exist, determinism is still not guaranteed, and larger max_tokens settings give less deterministic responses34. A provider's silent model or retrieval update inside the measurement window looks the same as run-to-run spread, and repeats alone cannot separate the two. Published recommendations for the run count depend on the target: one run per prompt and day over a large portfolio9, at least seven runs per prompt and day for per-brand detection2, at least ten responses for a quick per-prompt estimate10, usually at least 60 to 100 to know an AI's set of recommendations1. There is no agreed minimum.

Distinct from

From Measurement Consistency: inconsistency is the method moving between waves; volatility is the spread that remains after the method is frozen. From AI Citation Decay: decay is a sustained loss of citations; volatility within a period and the weekly rotation of sources are the noise against which it is read. From Sentiment Drift: drift is a directional change over time in how a brand is described; volatility is non-directional spread around a level. A drift shows once it leaves the band, or as a run of small steps in the same direction. From Platform Divergence: divergence is the difference between providers for the same prompt; volatility is the spread within one provider, so a gap between two platforms counts only if it exceeds the bands of both. From API vs UI Measurement: the access path shifts the level of a measurement and is fixed by design; volatility is the spread within one path.

Common mistakes

  • Reporting the brand list or the rank from one answer. In one study two lists in the same order came up about once in 1,000 runs1.
  • Setting temperature to 0 or fixing a seed and treating the answers as repeatable. The providers document that neither guarantees identical outputs354.
  • Applying the band of the overall figure to a single platform or prompt cluster. Fewer prompts per slice usually mean a wider band.
  • Reading a wave-to-wave move as the effect of a content change without checking it against the band. Without the band, an effect and noise look the same.
  • Reading a weekly change in cited sources as a change over time without same-window repeats: single weekly snapshots mix run-to-run spread with change over time82.

Where consensus is missing

There is no agreed minimum number of runs and no agreed way to compute a band for a slice of many prompts. Research metrics exist for agreement across N runs (TARr@N on raw output, TARa@N on parsed answers)7, but they measure identical answers, not the stability of a brand rate. Prompt wording is a separate axis: in few-shot benchmark tasks on open models, formatting changes alone moved accuracy by up to 76 points, and the authors recommend reporting a range across plausible formats11. Repeats of one prompt do not cover that axis; the prompt set has to (Prompt Coverage).
